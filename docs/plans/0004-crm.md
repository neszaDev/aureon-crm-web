# Plan 0004: the Aureon CRM frontend

## Context

The owner asked (2026-10-17) for a complete multi-tenant CRM template on both boilerplates. The
product specification, data model, permission matrix and API contract live in the backend repo
(branch `feat/crm`): `docs/crm/README.md`, `data-model.md`, `permissions.md`, `api.md`, and the
shared plan with the acceptance checklist, `docs/plans/0004-crm.md`. This file covers the
frontend's part.

## Decisions

| Question | Decision | Why |
|---|---|---|
| Branch | `feat/crm` (from `dev`), not merged without the owner's approval | The boilerplate stays generic |
| Signed-in home | `/app`: the caller's workspaces (one → opened directly, none → create form). The CRM lives at `/app/{workspaceId}/...` | The workspace id in the URL makes tabs and links unambiguous; the backend checks membership on every call |
| Boilerplate pages | Stay at `/dashboard/**`, unchanged in behaviour, reachable from the account menu | "Existing features keep working"; they double as a component gallery |
| Protected paths | `src/proxy.ts` protects `/app` as well as `/dashboard`; sign-in and sign-up redirect to `/app` | Same session rules; `Auth.e2e.ts` must stay green |
| Invitations | `/invite/{token}` (public, centered layout): preview, then accept (signed in with the invited email) or create the account through the link | Mirrors the backend's invitation endpoints |
| Code layout | `src/app/[locale]/(auth)/app/**`, `src/components/crm/**`, `src/actions/crm/*`, `src/libs/api/CrmQueries.ts`, `src/validations/crm/*`, locale namespaces prefixed `Crm` | CRM code is separate from the boilerplate's and easy to find |
| Data flow | Unchanged rules: reads in `CrmQueries.ts` from server components, writes in server actions with zod + `toActionError`, `revalidatePath` after writes; lists driven by URL search params (`q`, filters, `sort`, `direction`, `page`) | Server-side search and paging; shareable URLs; no client data fetching |
| Forms | react-hook-form + zod in dialogs/sheets; submit disabled while pending; 409 version conflicts tell the user to reload | Prevents double submits and silent overwrites |
| Pipeline board | `@dnd-kit` drag and drop, plus a "Move to" menu on each card (keyboard and touch); the card moves only after the server confirms, with a pending state; a failed move is reported with a toast and the card stays put | A drop never looks successful when the write failed |
| Charts | shadcn `chart` (recharts), already installed | |
| Look | New original design system "Aureon" (professional SaaS), light and dark tokens, theme stored in a cookie and applied server-side (no flash). `DESIGN.md` and `PRODUCT.md` are rewritten for the CRM | The Marksheet look was a placeholder for the test-results demo |
| Languages | `en` (default), `fr`, `th`; every key in all three (the i18n check stays strict) | |
| New dependencies | none | |

## Routes

| Path | Page |
|---|---|
| `/app` | workspace picker / create |
| `/app/{w}` | dashboard |
| `/app/{w}/companies`, `/companies/{id}` | list, detail (contacts, deals, tasks, timeline) |
| `/app/{w}/contacts`, `/contacts/{id}` | list, detail (deals, tasks, timeline) |
| `/app/{w}/leads`, `/leads/{id}` | list, detail, status, convert |
| `/app/{w}/deals`, `/deals/{id}` | board (default) or `?view=list`, detail with stage history |
| `/app/{w}/tasks` | views: mine, overdue, upcoming, completed, all |
| `/app/{w}/reports` | reports with a period filter |
| `/app/{w}/settings/...` | `workspace`, `members` (with invitations), `roles`, `pipeline`, `sources`, `audit`, `profile` |
| `/app/{w}/{entity}/export` | route handler streaming the backend's CSV (token stays in the httpOnly cookie) |
| `/invite/{token}` | invitation preview and acceptance |

## Tests

- Unit (`*.test.ts`): validations, URL/search-param parsing, money and date formatting.
- Component (`*.test.tsx`): forms (validation messages, disabled while pending), data table
  sorting links, empty states.
- E2E (`tests/e2e/Crm*.e2e.ts`, real backend): the 10-step workflow from the brief, an
  unauthorized member, settings, and the boilerplate suites kept green. Locally with
  `--workers=1` against the backend branch (API on `:8081`).
